# 결제알림 수집기 (PayLog)

갤럭시(안드로이드)에 오는 카드·은행·페이·지역상품권 알림만 골라서, 금액·가맹점·카드·승인/취소를 뽑아 **본인 구글 시트**에 한 줄씩 쌓는 앱입니다. 쌓인 시트는 Claude가 Google Sheets 연결로 읽어 월별 지출, 카테고리별 합계, 정기결제, 이상 결제를 정리합니다.

```
폰 알림 ──▶ 결제알림 수집기 (고른 앱만, 광고 제외)
              │  금액·가맹점·카드·구분 추출
              ▼
           폰 안 대기열 (오프라인이면 여기서 기다림)
              │  인터넷 연결되면 전송, 실패하면 간격 늘려 재시도
              ▼
           내 Apps Script 웹앱 ──▶ 내 구글 시트 '결제내역' 탭
```

## 원칙

- 앱이 인터넷으로 보내는 곳은 `Uploader.kt` 한 곳뿐이고, 주소가 `https://script.google.com/macros/s/…/exec`가 아니면 보내지 않습니다. 리다이렉트도 Google 주소가 아니면 멈춥니다.
- 외부 라이브러리 없이 안드로이드 기본 기능만 씁니다. 광고·분석 SDK 없음.
- 웹앱은 토큰이 맞아야 시트에 씁니다. 토큰은 폰에서 무작위로 만들어집니다.
- 고르지 않은 앱의 알림은 내용을 읽지 않고 버립니다. "최근 알림 보낸 앱" 목록용으로 앱 이름만 폰 안에 기억합니다.

## 파일

| 경로 | 내용 |
|---|---|
| `apps-script/Code.gs` | 시트에 행을 추가하는 웹앱 (중복 ID 무시, 수식 주입 방지) |
| `android/app/src/main/java/kr/paylog/collector/` | 앱 소스 |
| ├ `PaymentListenerService.kt` | 알림 수신, 앱 필터, 대기열에 넣기 |
| ├ `Parser.kt` | 금액·가맹점·카드·구분 추출 규칙 |
| ├ `DefaultApps.kt` | 기본 수집 앱 목록 (패키지명) |
| ├ `PendingStore.kt` | 폰 안 대기열 (SQLite) |
| ├ `Uploader.kt`, `UploadJob.kt` | 전송과 재시도 |
| └ `MainActivity.kt` | 설정 화면 |
| `android/app/src/test/.../ParserTest.kt` | 추출 규칙 테스트 (예시 알림 13개) |
| `.github/workflows/build-apk.yml` | GitHub에서 APK 자동 빌드 |

## 설치 순서

### 1. 구글 시트와 Apps Script

1. 새 구글 시트를 만듭니다 (이름 예: `결제내역`).
2. 메뉴 **확장 프로그램 → Apps Script** 를 열고, 기존 코드를 지운 뒤 `apps-script/Code.gs` 내용을 붙여 넣고 저장합니다.
3. 왼쪽 **프로젝트 설정(톱니바퀴) → 스크립트 속성 → 속성 추가**: 이름 `TOKEN`, 값은 4단계에서 폰 앱에 보이는 토큰.
4. 오른쪽 위 **배포 → 새 배포 → 유형: 웹 앱**
   - 실행 사용자: **나**
   - 액세스 권한이 있는 사용자: **모든 사용자** (폰 앱이 구글 로그인 없이 보내기 위해 필요. 토큰이 없으면 거부됩니다)
5. 권한 승인 후 나오는 **웹 앱 URL**(…/exec)을 복사해 둡니다.

코드를 고친 뒤에는 **배포 관리 → 수정 → 버전: 새 버전**으로 다시 배포해야 반영됩니다 (주소는 그대로).

### 2. APK 만들기

이 클라우드 환경에서는 안드로이드 SDK를 내려받을 수 없어 APK를 직접 만들지 못했습니다. 둘 중 하나로 만드세요.

- **GitHub (추천, PC 설치 불필요)**: 이 `paylog` 폴더를 GitHub 저장소로 올리면 `Build APK` 작업이 돌고, 저장소의 **Actions → 최근 실행 → Artifacts → paylog-apk** 에서 APK를 받습니다. 공개 저장소로 두면 "코드 전부 공개" 원칙도 같이 충족됩니다.
- **Android Studio**: `android` 폴더를 열고 ▶ 실행 (폰을 USB로 연결).

참고: 지금은 디버그 서명이라 GitHub에서 새로 빌드한 APK로 업데이트하면 "패키지가 충돌" 오류가 날 수 있습니다. 그럴 땐 지우고 다시 설치하세요 (폰 대기열이 비어 있을 때). 다시 설치한 뒤에는 앱의 "예전 토큰 붙여 넣기" 칸에 Apps Script의 `TOKEN` 값을 넣으면 Apps Script는 건드리지 않아도 됩니다.

### 3. 갤럭시에 설치하고 권한 주기

1. APK를 열어 설치. "출처를 알 수 없는 앱" 경고가 나오면 그 앱(내 파일·Chrome 등)에 설치를 허용합니다.
2. 앱 실행 → **알림 접근 설정 열기** → 결제알림 수집기 켜기.
   - 스위치가 회색으로 막혀 있으면 (안드로이드 13 이상, 직접 설치한 앱에 걸리는 제한): 앱 화면의 **앱 정보 열기** → 오른쪽 위 **⋮ → 제한된 설정 허용** → 다시 켜기.
3. **배터리 사용 '제한 없음'** 버튼 → 결제알림 수집기를 제한 없음으로. 갤럭시는 추가로 **설정 → 배터리 → 백그라운드 사용 제한 → 절전 예외 앱**에 넣어 두면 안전합니다.
4. 앱의 **토큰 복사** → 1-3단계 `TOKEN` 값으로 붙여 넣기.
5. 웹앱 주소 붙여 넣고 **주소 저장 → 연결 테스트**. "연결 성공"이 나오면 끝.

## 시트 열

`수신시각 | 거래시각(알림) | 구분 | 금액 | 통화 | 가맹점/내용 | 카드/계좌 | 할부 | 누적/잔액 | 앱 | 패키지 | 원문 | ID`

- 구분: 승인, 취소, 거절, 입금, 출금 (옵션을 켜면 미분류도)
- 금액은 항상 양수입니다. 취소·입금은 구분으로 판단합니다.
- 원문은 추출이 틀렸을 때 바로잡는 용도입니다. 앱 옵션에서 끌 수 있습니다.

## 알려진 한계

- 추출은 흔한 카드 문자·앱 푸시 형식을 흉내 낸 예시로만 검증했습니다. 실제 알림이 쌓이면 원문 열을 보고 규칙(`Parser.kt`)과 테스트를 보강하면 됩니다. chak 알림 문구도 아직 실물을 못 봤습니다.
- 같은 결제가 카드 앱 푸시와 문자로 둘 다 오면 두 줄이 됩니다. 한쪽 앱을 끄거나, 분석할 때 같은 금액·2분 안의 줄을 하나로 봅니다.
- 같은 문구의 알림이 10분 안에 또 오면 하나로 칩니다 (알림 갱신 중복 방지). 시각이 안 적힌 푸시로 같은 가게에서 같은 금액을 10분 안에 두 번 결제하면 한 줄만 남을 수 있습니다.
